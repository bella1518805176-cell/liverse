# LIVERSE 座位视野模拟器 · UI 设计方案

版本：概念方案 v1 · 2026-10-23

适用目标：面向观众的小程序，选择观演位置、预览舞台视角、比较候选座位。按微信小程序的竖屏场景提出布局建议，实际平台确定后调整原生导航和分享能力。

## 1. 设计结论

推荐方向：**黑色剧场空间 + 鲜橙色品牌导航 + 清晰的座位信息**。

产品对外名称建议使用「LIVERSE 观演视野」；「座位模拟器」可以作为功能说明。首页主文案建议「先看视野，再选座位」。

用户最关心的是：我在哪里、看向哪里、舞台有多大、有什么遮挡、和另一个位置相比怎样。界面围绕这些问题安排信息。

[查看 UI 方向与核心页面结构示意图](<D:/liverse/output/ui/LIVERSE_UI方向与页面结构.png>)。示意图用于对齐布局和视觉方向，地图、排座均为示意，画面使用苏州馆宣传影像，不代表某个座位实拍。

## 2. 从四份资料确认的品牌语言

审阅范围：北京 40 页、广州 43 页、上海 37 页、苏州 37 页，共 157 页。资料封面标注「场馆品牌手册 2026.09 v3」，实际内容以品牌介绍、场馆展示、设备和服务为主；未发现完整的数字产品色值、Logo 安全区、组件和交互规范。

以下「资料观察」来自源文件；「界面转译」和后文所有尺寸、色值、交互规则是本次设计建议。

| 品牌维度 | 资料观察与位置 | 界面转译 |
|---|---|---|
| 主配色 | 四馆封面、品牌介绍和章节页都反复使用鲜橙、黑、白 | 用深黑背景建立剧场感，以橙色建立导航、当前选择和主要操作 |
| 标识 | LIVERSE 大写字标，V 中包含放射线结构，常配「音宇宙」 | 使用官方 Logo 文件；放射线可延伸到加载和空状态插画，不重新绘制字标 |
| 图形 | 四馆第 3 页等章节页使用长橙色横线；第 6 页强调「跃动音胞」「橙色跳动」「音波流动」 | 将横线转成标题标记、当前楼层指示、位置连线；动态仅用于选中和加载反馈 |
| 空间与影像 | 大幅场馆、舞台、观演区照片，深色建筑材质与沉浸式屏幕 | 首页用真实场馆影像；主操作页让座位图与视角画面成为视觉主体 |
| 字体 | PDF 字体资源中反复出现 PingFangHK、JMeiHei、Helvetica / Helvetica Neue 与 Arial | 界面正文使用系统无衬线，标题用较粗字重；英文数字保持简洁、可辨识 |
| 版式 | 大标题、明显横向分隔、几何块面、图文分区，局部使用圆角卡片 | 大空间模块采用 8–12px 小圆角，主要信息左对齐，用留白建立层级 |
| 灯光色 | 蓝、紫、红等更多出现在演出影像和效果图中 | 保留在内容图像中，品牌控件继续采用稳定的橙黑体系 |

另一个直接依据：上海、苏州资料第 35 页、北京第 38 页、广州第 41 页包含购票小程序截图，已经使用黑色背景、橙色 Logo / 选中导航、白色文字和大幅演出影像。本方案可延续这组已出现的数字界面语言；截图不能证明现有小程序的实时版本、能力或库存接口。

不直接照搬宣传稿的小字号表格、密集橙色文字和大面积橙底。手机界面要通过白色正文、合理字号和收敛的强调色维持可读性。

## 3. 产品范围与信息架构

核心路径：

**选择场馆 → 选择演出 / 布局版本 → 选择楼层与区域 → 点选座位 → 预览视野 → 加入对比 / 收藏 / 分享**。

支持从演出、场馆二维码或分享卡片直接进入指定布局及座位，减少重复选择。回到地图时恢复楼层、缩放和选中座位。

建议首期包含：

1. 场馆入口页：四馆切换、场馆影像、进入看座。
2. 座位地图页：布局、楼层、区域、座位定位与快速信息。
3. 视野预览页：视角画面、空间关系、遮挡信息与数据来源。
4. 座位对比页：最多两个候选位置，支持同尺度切换。
5. 收藏 / 最近浏览：首期可作为入口页的轻量功能；不为此单独增加复杂「我的」体系。

产品中的「选中座位」表示正在查看的位置。首期不默认接入票务、座位库存或支付；若后续接入，增加真实的可售、已售、锁定状态。

## 4. 推荐视觉规范

### 4.1 色彩

以下是数字界面的候选色板，不是从资料确认的官方标准色。源 PDF 带有色彩空间信息，不同渲染链路会有差异；北京封面一处平涂区域的本地渲染采样约为 `#FB4F16`。高保真阶段以品牌方提供的标准 sRGB 色值为准。

| 角色 | 建议值 | 使用方式 |
|---|---|---|
| 品牌橙 | `#FF5018` | 主按钮、选中座位、当前楼层、关键位置线 |
| 主背景 | `#0B0D10` | 页面、剧场画布外围 |
| 信息面板 | `#171A1F` | 底部信息卡、筛选区、浮层 |
| 次级表面 | `#242A32` | 未选控件、工具按钮 |
| 正文白 | `#F5F6F7` | 标题与主要信息 |
| 辅助灰 | `#A8ADB5` | 次级说明、未激活标签 |
| 控件边线 | `#68727E` | 需要辨识的边界、未选座位轮廓；装饰分隔可更暗 |
| 提示黄 | `#F3C46B` | 栏杆等遮挡提示，始终搭配图标与文字 |

基础页面可以约 75% 深色、20% 内容与中性色、5% 橙色理解；该比例不约束照片和视角画面。橙底主按钮使用近黑色文字，避免小号白字的对比不足。正文对比度按至少 4.5:1、重要图形和控件边界按至少 3:1 验证。

### 4.2 字体、尺寸与组件

- 中文采用系统无衬线：iOS 使用 PingFang SC，Android 使用平台系统字体；不默认分发 PDF 中的嵌入字体。
- 页面主标题 24–28px，区块标题 18–20px，正文 14–16px，辅助文字 12–13px。座位编号等核心信息不依赖小号辅助字承载。
- 排号、座号、距离采用清楚的数字层级；同列数字可使用等宽数字样式。
- 以 375px 逻辑宽度为起点，对应 750rpx；页面边距 16px，常用间距 8 / 12 / 16 / 24px。
- 按钮高度建议 48px，常规交互热区至少 44 × 44px；小图标通过容器扩展热区。
- 面板圆角 8–12px，底部抽屉上角可用 16px；主要按钮使用 8px 左右圆角。
- 图标采用统一 1.5–2px 线性风格，常用图形为定位、楼层、放大、复位、视角、对比、收藏。
- 沉浸页面使用深色导航，适配原生胶囊、状态栏和底部安全区；不在全屏地图内常驻全局 TabBar。

## 5. 四个关键页面

### 5.1 场馆入口页：建立品牌与选择目标

页面构成：

1. 顶部：官方 Logo + 当前城市切换。
2. 首屏主视觉：当前馆真实建筑或观众朝向舞台的影像，配「先看视野，再选座位」。
3. 城市切换：北京 / 广州 / 上海 / 苏州共用同一视觉规范；用各馆影像和名称识别差异。
4. 场馆卡片：场馆名称、已开放的预览类型、主入口「进入看座」。
5. 下方：最近查看的位置、收藏入口及精简的场馆信息。

首页采用一张主视觉和明确的单一主操作。演出海报可作为演出选择内容，不承担所有场馆的通用主视觉。

若布局会随活动改变，进入地图前选择演出 / 场次。没有演出数据时显示具名的「标准布局 · 版本日期」；避免让用户误以为是任意演出的最终配置。

### 5.2 座位地图页：核心工作界面

建议竖屏自上而下排列：

| 层级 | 内容与占比建议 |
|---|---|
| 顶部导航 | 返回、场馆名称、当前演出或标准布局入口 |
| 紧凑切换栏 | 楼层、区域，必要时增加排号 / 座号搜索 |
| 主画布 | 保证约 55%–65% 的可用内容高度；显示舞台、座位、通道、结构遮挡 |
| 工具与图例 | 放大、缩小、复位、当前楼层小地图；采用「可预览 / 当前查看 / 暂无视野」等准确标签 |
| 底部信息卡 | 默认收起；选中后显示楼层、区域、排座、视野来源及「查看视野」 |

地图交互按「全馆 → 区域 → 座位」渐进展开。全馆视图先点区域，放大到可准确选择时再显示座号。座位密集时先放大，避免扩大的热区彼此覆盖。

舞台在初始视图中置于上方，保留真实朝向、区域形状、过道与座位关系。若允许旋转，持续显示舞台方向与复位入口。

视觉状态建议：

| 状态 | 表达 |
|---|---|
| 有视野资料、未选 | 浅色轮廓座椅，保持足够边界对比 |
| 当前查看 | 橙色实心 + 清晰位置标记，配排座标签 |
| 已加入对比 | 高对比描边 + A / B 标记，同时显示当前查看标记 |
| 暂无视野 | 暗色填充 + 斜线符号；仍可点开座位信息，卡片解释「该位置暂无视野」 |
| 结构遮挡 | 在真实位置绘制栏杆、立柱、控台等轮廓，配说明入口 |

如果没有票价信息，不在地图中生成票价色带；如果接入票价，用低饱和区域底色和明确图例表示，橙色仍专用于当前选择。不能用「无预览」推断「已售」或「不可购」。

底部卡片只保留一个主按钮「查看视野」，次要操作「加入对比」采用文字或描边按钮。展开卡片时显示更多信息，折叠后恢复地图空间。

### 5.3 视野预览页：让观众判断舞台空间关系

默认使用大画面与可收起的信息卡。视角画面占可用区域约 65%–75%，支持横屏全屏查看；预览中保留一个不遮挡舞台的入口返回座位图。

画面上方：返回、位置名称、预览类型标签。

画面内部：极简视线中心提示、复位视角、全屏；有真实全景或模型时提供拖动环视。静态照片不显示「360°」等无法实现的控件。

下方信息：

- 位置：楼层 / 区域 / 排 / 座。
- 舞台关系：有校准数据时显示距舞台约多少米、偏转角或俯视角；无数据时隐藏数值。
- 遮挡说明：具体到「该采集点可见前沿栏杆」等事实，不仅给笼统的「视野较差」。
- 资料来源：座位实拍、区域参考或模型模拟，附适用布局 / 场次、采集或更新日期。
- 操作：换座位、加入对比、收藏、分享；不同时突出所有按钮。

区分两种缩放：「画面放大」只方便看细节；「标准视角」保留用于座位比较的统一尺度。照片的数码放大不能被描述为真实人物大小或实际人眼视野。

不默认展示「视野 98 分」「无遮挡」「最佳座位」等无依据的评价。参考图中的局部无遮挡，不等同于活动当天没有人群或临时设备遮挡。

### 5.4 座位对比页：支持选择决策

首期最多比较两个位置。竖屏默认 A / B 切换同一大画面，并提供简短的对比信息；可展开上下对照。横屏可以左右对照。

可比项目：排座、布局版本、距舞台距离、横向角度、遮挡说明、影像类型。价格只在有来源时显示。

两份视野资料使用相同基准视角、相近裁切和一致缩放；资料不能校准时明确显示「不同拍摄条件」，不按人物大小做直接优劣排序。

## 6. 四馆差异如何进入 UI

| 场馆 | 资料中可确认的结构线索 | 对界面的影响 |
|---|---|---|
| 北京 | 第 8–9 页为 1F / 2F 平面，第 13–17 页包含一层观众区、二层座席区和不同朝向照片 | 强调楼层切换及二层侧向位置；照片先区分拍摄方向，舞台拍向观众的照片只用于空间参考 |
| 广州 | 第 8 页为六边形平面，第 12 页展示前后区、前后看台与 VIP 包间；第 9 页 B1 为相关空间布局 | 保留六边形与各看台位置；包厢采用区域 / 包厢入口，真实存在逐座数据时再提供座号；B1 不因出现在资料中就自动成为观众选座楼层 |
| 上海 | 第 8–10 页含 1F / 2F / 3F 平面，第 15 页为二层座席区展示 | 数据结构支持多个楼层；具体开放的观演层和用户所见楼层名称需与场馆正式座位图核对 |
| 苏州 | 第 8–9 页为 1F / 2F 平面，二层有 A / B / C 区标识，第 14 页为二层座席区照片 | 楼层 + 区域双层导航，保留真实 A / B / C 命名和通道关系 |

四馆共用色彩、字体、按钮、卡片和交互规则；每馆使用自己的地图数据、楼层名称、区域、影像与遮挡资料。

有些一层空间随活动采用站席或临时座椅。站席模式使用区域与「参考观察点」，不生成虚构的固定排座，也不承诺站票对应固定观看位置。

## 7. 预览资料的三种呈现合同

| 类型 | 用户看见的标签 | 可表达的精度 | 必需条件 |
|---|---|---|---|
| 座位实拍 | 座位实拍 | 明确采集座位在当时条件下的画面 | 座位编号对应、相机位置 / 高度 / 镜头信息、布局版本、采集日期 |
| 区域参考 | 区域参考 · 邻近观察点 | 某区域或最近采集点的空间感 | 采集点在地图中的位置，说明与所选座位不完全一致 |
| 模型模拟 | 模型模拟 | 在已建模布局和观察高度下的空间关系 | 经核验的空间模型、座位坐标、台高与台口、栏杆 / 立柱 / 控台等遮挡数据 |

现有宣传资料足以支撑品牌方向、入口影像与部分区域参考，不能单独支撑逐座准确视野。资料中既有现场照片，也有效果图和示意图，使用前应登记素材类型和拍摄朝向。

建议先具备「可用座位图 + 区域参考」的完整体验，再根据真实资产接入逐座实拍或 3D。是否选择 3D 由可获得的场馆数据和精度要求决定；UI 为三类资料预留一致容器。

建议页面中的来源说明直白表达，例如：「区域参考：画面来自本区采集点，与所选座位可能有差异。」这属于帮助观众理解图像的必要信息。

## 8. 动效、状态与小程序体验

- 选中座位：约 120–180ms 的颜色 / 轮廓反馈，配一次轻触感；支持关闭振动。
- 地图切换区域：约 200–300ms 平移缩放，保持舞台方向；减少动态效果设置下简化过渡。
- 打开预览：先显示该位置的缩略图与明确加载状态，再加载全景或模型；不使用虚假的进度百分比。
- 预览加载失败：保留所选座位与返回路径，提供重试；有参考图片时提供「查看区域参考」。
- 没有预览：展示附近已采集观察点，标明位置关系；不静默替换为别处照片。
- 布局发生变化：明确当前版本，避免从旧收藏直接显示不再对应的排座。
- 退出预览：恢复地图原有选中、楼层与缩放，不强迫重新找座。
- 不依赖颜色表达状态；选中、对比、无资料等搭配符号与文字。表单、卡片及列表支持系统字号设置。
- 地图和全景容易与页面滚动冲突：地图页锁定主体滚动，详细说明放入抽屉；展示清楚的复位操作。
- 不因进入看座而强制登录；需要云端收藏时再明确引导。分享卡片包含场馆、布局与位置，不把收藏误写成订座成功。

## 9. 首期范围与后续扩展

**P0：核心看座闭环**

- 四馆选择及必要的布局选择。
- 楼层 / 区域 / 座位地图与编号查找。
- 根据实际素材提供静态、全景或模型视野，明确资料类型。
- 空资料、加载失败、布局版本等关键状态。
- 收藏或最近浏览、位置分享。

**P1：辅助决策**

- 两座对比。
- 经核验的遮挡提示和最近参考点。
- 基于真实数据的距离、方向等指标。

**P2：有相应数据与业务合作后扩展**

- 全馆逐座模型预览、可调观察高度。
- 与具体演出舞美版本匹配。
- 票务价格、库存、外部购票入口。

建议先用苏州的某个二层固定座席区域验证完整流程，前提是能拿到相应的正式座位图和视野素材；随后复用到其他区域与场馆。

## 10. 高保真阶段交付清单

设计应交付：首页、地图未选态、地图选中态、楼层切换、座号搜索、视野预览、来源说明、暂无视野、加载失败、对比、收藏 / 最近浏览、分享卡片，以及横屏预览适配。

组件应覆盖：按钮、楼层切换、区域标签、座位状态、舞台标识、地图工具、位置卡、来源标签、遮挡提示、底部抽屉与空状态。

在此之前需要补齐三组输入：

1. **品牌资产**：官方矢量 Logo、标准屏幕色值、字体与影像授权范围。
2. **场馆资产**：正式座位图、座位编号与坐标、可开放楼层 / 区域、布局版本；若做模型，补充必要空间几何与遮挡数据。
3. **视野资产**：已有照片 / 全景 / 模型清单，每份素材对应的采集点、朝向和布局；是否区分演出或场次。

以上输入影响预览精度与控件能力，不影响本轮橙黑视觉方向和核心页面结构的确定。
