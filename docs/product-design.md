# LIVERSE 观演视野小程序产品设计文档

版本：v0.1；日期：2026-10-26；状态：首版评审稿。

用途：作为小程序工程搭建、页面设计、接口设计和验收的共同依据。本文中的首版功能分期与量化指标为建议方案，尚待产品评审确认；不代表全部业务细节已获主办方确认。

## 1. 产品定位与已确认决策

帮助北京 LIVERSE 的观众在观演前了解位置、判断舞台视角，在观演后分享实拍并保存现场记录。

| 项目 | 当前结论 | 依据 |
|---|---|---|
| 首发场馆 | 北京 LIVERSE | 本次对话确认 |
| 目标平台 | 面向公众使用的微信小程序，优先稳定和交互流畅 | 本次对话确认 |
| 产品路线 | 原生小程序页面为主，3D 为独立模块，配网页管理后台 | 前序技术建议及用户继续推进；适配方案仍需真机验证 |
| 参考产品 | 视野 Live 的选位、视角预览、实拍、收藏对比及观演记录能力 | 前序公开页面、资源和接口调研 |
| 品牌方向 | 黑、白与品牌橙；优先使用授权场馆影像和官方标识 | 已有 UI 方案；数字色值待品牌方确认 |
| 场馆数据 | 尺寸、座位编号、坐标和遮挡资料暂空，待与主办方对齐 | 用户明确要求 |
| 当前交付 | 产品设计文档；暂不创建小程序工程 | 本轮请求 |

已有 UI 概念方案涉及北京、广州、上海、苏州四馆。本轮以北京单馆为首发范围，其他城市保留扩展能力，不在首版首页展示尚未开放的场馆。已有方案中的苏州试点建议由北京首发取代；旧文件保留为历史设计参考。

功能参考不代表可复制参考站代码、照片、用户资料或场馆数据。新产品使用自有或获授权的资产；参考站的排座模型不作为 LIVERSE 的事实依据。

## 2. 用户与核心任务

| 用户 | 核心问题 | 完成标志 |
|---|---|---|
| 准备购票的观众 | 两个位置的舞台距离、角度和结构遮挡有什么不同？ | 找到候选位置，查看资料并完成对比 |
| 已有票的观众 | 我的楼层、分区和排座在哪里？ | 定位票面位置，打开对应视角或区域参考 |
| 演出后的观众 | 怎样让自己的照片帮助后来的人？ | 投稿后可追踪审核状态，审核通过后公开 |
| 主办方／运营 | 如何维护场次布局、照片和错误信息？ | 发布经确认的资料、审核内容、处理纠错并可追踪操作 |

产品帮助观众理解位置，不承诺某座位最佳、不承诺无遮挡，也不模拟动态人群、实时灯光和最终拍摄画质。没有票务对接时，查看和收藏均不占座。

## 3. 版本范围与优先级

P0 为建议的正式首版范围；P1、P2 为后续迭代。工程准备阶段可以先完成 P0 的页面与业务框架，但不等同于具备正式发布条件。

| 需求 ID | 优先级 | 能力 | 首版规则与边界 |
|---|---|---|---|
| FR-01 | P0 | 北京场馆与场次入口 | 选择具体演出布局；无场次时只展示已发布且具名的参考布局 |
| FR-02 | P0 | 2D 地图与位置查找 | 楼层／区域选择、缩放复位、排座搜索；逐座模式须有已核验数据 |
| FR-03 | P0 | 3D 位置视角 | 总览、位置定位、环顾与坐站姿；以已发布模型及其适用布局为准 |
| FR-04 | P0 | 两位置对比 | 最多两个候选位置；同一布局下采用相同基准视角，默认仅激活一个交互画面 |
| FR-05 | P0 | 收藏、最近浏览与分享 | 游客本地收藏，登录后云端同步；分享指定布局版本和位置 |
| FR-06 | P0 | 实拍与体验浏览 | 按场次、区域和标签筛选；照片预览、关联位置、标记有用与举报 |
| FR-07 | P0 | 登录与账号 | 微信登录；头像昵称由用户主动选择；登录失败保留当前任务 |
| FR-08 | P0 | 实拍及文字投稿 | 登录后投稿、明确公开授权、图片处理、审核后展示、可查看状态和删除 |
| FR-09 | P0 | 我的与反馈 | 收藏、投稿记录、反馈、举报进度、隐私入口及账号删除申请 |
| FR-10 | P0 | 数据与内容后台 | 场馆布局版本、媒体、投稿审核、举报反馈、发布回退与操作记录 |
| FR-11 | P0 | 能力降级与恢复 | 3D 不可用时返回 2D／已有参考图；重试和返回保留当前选择 |
| FR-12 | P1 | 手机取景模拟 | 变焦、画幅、方向与导出；只比较构图，不预测画质 |
| FR-13 | P1 | 观演回忆 | 私密记录、照片和封面；主动公开需审核，默认私密 |
| FR-14 | P1 | 观演足迹与海报 | 基于用户记录与展示选择生成，不采集 GPS 推断观演事实 |
| FR-15 | P2 | 多馆与账号扩展 | 其他城市；确有跨端需求后再增加手机／邮箱绑定与账号合并 |
| FR-16 | P2 | 票务合作 | 有正式接口和授权后另行设计价格、库存或购票跳转 |

首版不做支付、锁座、余票、交易订单、位置评分排行榜、关注私信或视频投稿。不把图上的颜色解释为票价、可售或已售状态。取景、回忆和足迹仍属于完整产品规划，不因首版分期而删除。

## 4. 信息架构与页面清单

全局采用三个 Tab：「看座」「实拍」「我的」。北京为默认场馆，不增加多馆搜索首页。收藏和对比从位置页、我的进入；沉浸地图和预览页作为独立页面，不显示全局 TabBar。

| 页面 ID | 页面 | 主要内容与操作 |
|---|---|---|
| PG-01 | 看座首页 | LIVERSE 标识、北京场馆真实影像、场次／参考布局、进入看座、最近浏览 |
| PG-02 | 场次选择 | 演出、日期、可用布局及版本；不可用场次明确说明，禁止默认为另一场 |
| PG-03 | 2D 座位地图 | 舞台、楼层、分区、排座查找、缩放复位、位置详情抽屉 |
| PG-04 | 视角预览 | 3D／实拍／区域参考切换、来源、位置、收藏、对比、分享 |
| PG-05 | 位置对比 | A／B 切换、对应资料及差异、移除或替换；可展开静态双图 |
| PG-06 | 实拍列表 | 场次和区域筛选、照片／体验切换、分页、投稿入口 |
| PG-07 | 分享详情 | 多图、拍摄信息、作者主动公开资料、位置、文字、点赞式有用标记、举报 |
| PG-08 | 投稿编辑 | 选范围与照片、位置和场次、可选设备倍率、体验标签、署名及公开确认 |
| PG-09 | 我的 | 登录、收藏、最近浏览、我的投稿、反馈、举报、隐私和设置 |
| PG-10 | 收藏与投稿管理 | 位置重访／删除；投稿待审核、已公开、未通过、已下架及处理说明 |

页面数据不写死；同一位置详情用于地图、收藏、分享和实拍定位，避免各入口指向不同座位。

## 5. 关键流程与交互规则

### 5.1 观演前找位置

看座首页 → 选场次或具名参考布局 → 楼层／区域 → 票面排座或参考观察点 → 查看来源 → 进入视角 → 收藏／加入对比／分享。

- 未登录可完成公开资料浏览、看座、预览和分享。
- 初始地图使舞台朝上；可旋转时保留舞台方向和复位按钮。区域到座位逐级放大，密集时不扩大座椅热区造成误选。
- 座号搜索必须匹配当前布局的真实编号。无结果提示核对楼层与分区；不跳到附近座位并当作命中。
- 无逐座数据时只能选择区域或参考观察点，不显示虚构的排座。站席不分配固定座位。
- 位置抽屉显示位置、资料类型、布局、更新时间，一个主操作「查看视野」，次操作收藏／对比。
- 退出预览恢复楼层、地图缩放、选中位置和列表筛选。取消登录也恢复原任务。

### 5.2 对比、收藏与分享

选择位置 A → 加入对比 → 继续找位置 B → 打开对比 → 切换相同基准视角 → 保存候选位置。

- 最多两个位置；第三个先选择替换 A 或 B，不静默覆盖。同一位置不可重复加入。
- 默认比较同一布局版本；跨版本位置先切换到共同的可用版本，无法对应时分别重访，不生成可比结论。
- 游客收藏存在本机。首次登录时询问是否导入，按布局版本与位置标识去重；退出后不向游客展示云端账号资料。
- 分享参数包含公开布局版本与位置标识，不包含登录凭据或用户私密记录。私密页面不生成公开分享卡片。
- 收藏遇到版本下架显示不可用原因；允许用户主动寻找新布局中的位置，不按相同座号自动迁移。

### 5.3 实拍浏览与投稿

查看位置或实拍列表 → 打开分享 → 看拍摄场次与位置 → 可进入对应模型位置；投稿时先登录 → 选分享范围 → 添加照片或体验 → 确认公开 → 提交审核 → 查看进度。

- 分享范围为「具体位置／区域」或「整个场馆」。不记得位置可选整个场馆，不能默认沿用当前模型选中的座位。
- 实拍一组最多 4 张，支持 JPG、PNG、WebP，原图每张最多 20 MB；建议压缩至最长边 2200px、处理后每张不超过 5 MB。数值为首版建议，客户端与服务端统一校验。
- 移除 EXIF／GPS 元数据；不依赖元数据清理处理画面中的票务二维码、证件等信息，上传前提供提醒及预览删除能力。
- 图片投稿可不写备注；纯文字体验必须有内容。现场感受建议最多 300 字，最多 6 个有效标签；设备和倍率选填。
- 场次、位置、排座、设备、署名和内容会随公开投稿展示，邮箱、手机号、内部用户 ID 不公开。
- 提交须主动勾选照片权利及公开授权。网络失败保留表单；返回离开前确认。首版草稿只保证当前编辑会话内保留，跨重启草稿不承诺。
- 服务端使用提交请求标识防止重复；上传成功但审核请求失败时可继续提交，不生成重复投稿。临时未关联图片定期清理。
- 首版已提交内容不直接覆盖编辑；更正可删除后重投。审核失败显示原因，删除后公开接口和媒体访问均应失效，并更新缓存。
- 有用标记按用户限制重复操作；举报支持位置错误、内容问题、隐私／版权等分类，不公开举报者身份。

### 5.4 登录与数据删除

仅在云端收藏同步、投稿或查看个人记录时要求登录。微信认证与头像昵称设置分开；不以认证为由强制获取手机号。

退出后清理账号缓存和私有页面数据；切换账号不得读取前一个账号的投稿、工单和收藏。删除账号需再次确认，并说明公开内容及备份处理规则；首版可提供人工处理入口，但须建立可追踪工单、负责人和告知期限，正式期限由运营确认。

## 6. 视觉与组件原则

沿用现有黑白橙方向。候选品牌橙为 `#FF5018`，背景 `#0B0D10`，主要文字 `#F5F6F7`；均为设计建议，不冒充品牌官方色值。正式影像、Logo 与字体遵循授权范围，首版使用系统字体。

- 内容列表和表单优先可读性，3D 画布保留舞台对比度，不强制用过暗材质营造氛围。
- 当前查看为橙色并搭配位置标记；对比位置用 A／B；暂无资料用符号与文字，状态不只靠颜色。
- 主要热区至少 44×44 逻辑像素；面板常规圆角不超过 8px。适配状态栏、微信胶囊及底部安全区。
- 工具操作使用统一图标并提供可读名称。楼层／预览类型用分段切换，坐站姿用开关，位置微调用滑块。
- 竖屏为基础，横屏为预览增强；不支持横屏的设备仍可完成全部核心任务。
- 正文和表单支持系统字号；正文对比度目标至少 4.5:1。选中反馈简短，尊重减少动效设置。

## 7. 资料精度、3D 和空数据策略

### 7.1 三种资料类型

| 类型 | 展示含义 | 不得推导的结论 |
|---|---|---|
| 座位实拍 | 对应明确座位、场次／布局及拍摄条件的照片 | 同座位其他场次一定相同、照片即人眼视野 |
| 区域参考 | 已知区域或邻近观察点的画面 | 精确对应用户所选座位 |
| 模型模拟 | 在指定模型、布局和眼高下的空间估算 | 已实测的无遮挡结论、真实演出光效或摄影画质 |

每份资料记录来源、类型、适用布局、采集／更新时间和核验状态。未核验不能标「精确座位实拍」；无距离数据时隐藏米数，不能用默认数字填充。当前已知一层前区、一层后区、二层的结构仅作待核实线索，不视为完整正式座位分区。

### 7.2 开发环境与公开环境

当前阶段可以使用测试楼层、测试座位和简化几何验证交互，统一标为「开发示例」，通过构建配置与正式数据隔离。不得把示例号当作 LIVERSE 正式编号。

公开环境按布局的已发布能力显示入口：有经核验区域图则提供区域参考；有经核验逐座数据才开放排座查找；有通过校准和真机验收的模型才开放 3D。资料未齐时不向公众发布虚构地图或模型，开发者工具中的完整示例可继续迭代。

3D 功能属于目标首版；资料未齐可先做受限的区域参考试运营，但须作为缩小范围单独确认，不宣称完成逐座 3D 正式版。

### 7.3 3D 体验与性能原则

建筑模型与座位数据分离；座椅采用批量实例绘制。默认先完成 2D，再按需加载 3D；公共资源走 CDN，按布局版本缓存。只加载当前场馆所需资源。

观众视角保留真实结构遮挡，总览可隐藏屋顶等结构以便选位。相机定位使用座位坐标与独立眼高；坐姿／站姿眼高为产品模拟参数，不表述为所有观众的真实高度。设备不支持或发生上下文丢失时提供重建场景、返回 2D 和已有参考图，不显示虚假的 3D 加载百分比。

对比默认一个渲染器，通过切换机位或静态快照展示第二位置。页面隐藏暂停渲染，退出释放资源；前后台切换后保留位置，必要时重建画布。

## 8. 关键状态与异常处理

| 场景 | 用户看到的状态 | 恢复方式 |
|---|---|---|
| 首次加载 | 结构稳定的占位与真实加载状态 | 完成后替换；超时给重试，不无限等待 |
| 场次未收录 | 暂无本场布局 | 主动选择具名参考布局，不自动替代 |
| 未核验／暂无逐座数据 | 区域参考或资料待补充 | 可浏览已有内容，不显示不存在的座号 |
| 3D 失败／低性能 | 预览不可用或简化画质 | 重试、返回座位图、已有参考图 |
| 照片为空 | 当前条件暂无实拍 | 清除筛选或投稿，不用别区照片冒充 |
| 登录取消／过期 | 保留选择、表单及明确提示 | 继续公开浏览或重新登录后恢复任务 |
| 上传／提交超时 | 标记失败步骤，保留可重试内容 | 重试同一请求，避免重复投稿 |
| 内容已删除／下架 | 内容不可用 | 返回列表或场馆；不可绕过原链接访问媒体 |
| 布局升级／旧链接 | 版本与可用性说明 | 查看仍公开的旧版，或主动选择新版 |
| 后端维护／限流 | 可理解的暂不可用提示 | 延迟重试，已有公开缓存显示更新时间 |

空、加载、失败、无权限和已下架分别设计，不能全部表现成没有内容。无网络时不保证离线服务，但保留本机收藏与当前未提交表单，不伪造提交成功。

## 9. 数据对象与接口职责

以下为设计契约，具体技术栈、数据库和 URL 在工程搭建时确定。

| 对象 | 关键字段／关系 | 必须保持的约束 |
|---|---|---|
| Venue | 场馆 ID、名称、城市、媒体 | 北京首发；ID 不随名称变化 |
| Event | 演出、场次日期、时区、关联布局版本 | 同馆不同场次可有不同布局 |
| LayoutVersion | 版本 ID、场馆、适用场次、来源、能力、发布状态 | 草稿／已发布／已下架；已发布版本内容不可原地覆盖 |
| Section／Seat | 楼层、区域、排座字符串、坐标、朝向 | 编号保留字母和前导零；唯一性包含版本与区域 |
| Viewpoint | 座位或区域关联、眼高、资料类型 | 区域观察点与精确座位分别表示 |
| Media | 对象存储标识、归属、类型、授权、审核与访问状态 | 私有和待审资源不使用永久公开 URL |
| Contribution | 作者、场次、位置、文字、设备、图片、审核状态 | 文字和图片一起审；模型标点另存，不覆盖票面信息 |
| Favorite | 用户或本机归属、布局版本、位置标识 | 幂等收藏，账号隔离；去重不跨布局版本 |
| User | 微信身份映射、主动选择的资料、账号状态 | 服务端交换登录凭证；密钥不进入客户端 |
| Feedback／Report | 提交者、对象、分类、状态、回复 | 提交者及授权运营可见，回复可追踪 |
| AuditLog | 操作者、对象、动作、时间、变更摘要 | 布局发布、审核、下架与权限操作可追溯 |

接口职责分为公开目录／布局、公开实拍、登录会话、个人收藏、上传投稿、工单、运营管理。公开接口不返回待审核内容和身份字段；个人及运营接口逐请求鉴权与对象归属校验，不能只在页面隐藏入口。

图片上传需服务端授权、文件类型与解码校验、体积限制、元数据清理和审核；不能只依赖扩展名和前端压缩。删除、下架同步限制原图、缩略图和 CDN 访问，明确缓存失效方案及处理时限。

## 10. 运营后台与内容生命周期

后台建议角色为内容运营、场馆数据管理员和系统管理员。内容运营处理投稿、举报和回复；场馆管理员维护布局和来源；系统管理员分配权限。角色是否兼任由团队确认，权限必须在服务端执行。

布局：草稿 → 校验与预览 → 确认 → 发布；纠错生成新版本，必要时下架旧版。回退指重新启用经过核验的历史版本，保留审核记录和版本引用。

投稿：待审核 → 已公开／未通过；已公开 → 已下架／作者删除。仅公开状态可进入公共列表与分享详情；举报不自动等于下架，涉及隐私等紧急情况允许授权运营先下架再处理。处理结果在投稿记录或举报工单中可见。

反馈／举报：已收到 → 处理中 → 已解决／不予处理，记录说明和回复。保留日常巡检、待审积压、图片异常及接口告警入口；自动内容检测不能替代人工处理和申诉。

## 11. 隐私、安全与正式发布条件

- 明确小程序运营主体、用户协议、隐私政策、数据用途、存储及删除规则和联系渠道，实际主体名称等待客户确认。
- 微信登录、头像选择、相册上传和图片保存按实际能力声明用途，并按需申请权限；拒绝权限仍可浏览公开内容。
- 用户公开授权针对本次投稿内容，不把登录当成对全部记录的公开授权；未来回忆默认私密。
- 按账号和请求特征限制投稿、举报及有用标记频率；日志不记录会话密钥、上传签名和敏感表单原文。
- 正式环境使用 HTTPS、已配置的小程序合法域名、独立密钥和最小权限；开发数据与正式数据分离。
- 根据实际服务类目核对小程序备案、主体资质、UGC 审核及平台审核要求，落实审核值守与反馈渠道后上线。
- 发布需有监控、数据库与媒体备份、恢复演练、应用版本回退和布局下架预案。性能降级不能代替权限和数据一致性保障。

## 12. 性能与稳定性验收建议

以下为待真机验证的初始目标，不是已完成的性能结果。基线：iOS、主流安卓、较低配置安卓各至少一台真机；首轮测试记录具体型号、系统、微信与基础库版本，并以持续 10 Mbps、RTT 约 100ms 的网络条件作为对照。

| 指标 | 建议目标 | 测试条件与计时口径 |
|---|---|---|
| 冷启动入口可操作 | P95 不超过 3 秒 | 从启动到场次入口可点击；至少 30 次独立冷启动 |
| 2D 地图首次可操作 | P95 不超过 2 秒 | 从进入地图到能点选区域；清除布局资源缓存，至少 30 次 |
| 3D 首帧 | P95 不超过 5 秒 | 点击预览至有效场景首帧；分别记录冷／热资源，至少 30 次 |
| 3D 环顾 | 中档设备平均至少 30 FPS | 连续拖动与缩放 60 秒，同时记录卡顿；低配失败则简化或回到 2D |
| 长时间使用 | 无崩溃、无持续资源增长 | 连续使用 20 分钟、进出 3D 20 次、前后台切换 10 次 |
| 上传与弱网 | 可恢复，无重复投稿 | 单图和四图；断网、超时、重试、登录过期、重复点击 |

后端容量目标按主办方预估峰值、图片流量和活动推广时间补充，未获得流量预估前不承诺并发人数或服务可用率。正式发布前完成鉴权、账号隔离、内容下架及发布回退验证，不能仅以页面截图通过验收。
