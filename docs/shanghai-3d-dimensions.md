# 上海 LIVERSE：3D 模型尺寸与座位落位依据

日期：2026-11-11。目标布局：**全坐席1208；1F 800座，2F 408座**。本次交付尺寸与依据，不改网页、不制作新3D场景。

目前可以沿用原 SKP 几何搭建场馆总览；还不能将全部1208座标为“真实位置已校准”。已经确认座位身份与分区，尚缺一楼椅距/排距/定位、二楼逐排与台阶的对应，以及若干版本冲突的判定。下文列出完整建模参数类别，未能从资料确认的值明确留空。

配套文件：

- [三维参数 JSON](data/shanghai-3d-dimensions.json)：44条尺寸记录、12个主要看台水平面、29个主体根组件、1208条座位记录、26类待定参数。
- [1208座位清单 CSV](data/shanghai-1208-seats.csv)：每个座号及对应 Excel 单元格；真实 XYZ 和朝向为空。
- [原始依据摘录 JSON](data/shanghai-3d-evidence.json)：来源文件 SHA-256、选定 CAD 实体、SKP 组件变换/包围盒、水平面顶点及逐排原表单元格。它是可审计的摘录，不是完整场馆网格。
- [建筑图看台剖面摘图](figures/shanghai-cad-tier-section.png)：说明 CAD 标高和小踏步关系，版本尚未裁定，不能直接当作竣工尺寸。

## 1. 使用口径与资料优先级

| 数据类别 | 依据 | 本次如何使用 |
| --- | --- | --- |
| 1208座数量/编号/分块 | `material/上海Liverse座位分布图表.xlsx` → `全坐席1208` | 作为本次排座身份依据；不能由单元格宽高推算米数 |

| 建筑和看台剖面 | `material/X-01-A-100_t3.dwg`、`S-01-0300-剧场改造.dwg` | 与SKP交叉核对；旧排座及标高冲突单独保留 |
| 屏体 | `material/上海乔高屏体系统拓扑图-20250529(1).dwg` | 读取标注、像素和箱体尺寸；同文件内有多版方案 |
| 吊点 | `material/150路吊点图2502-24(1).dwg` | 保留局部标注；“150路”不等于已取得150个可用XYZ点 |
| 其他结构资料 | `S-01-0001-总说明.dwg`、`A-01-000_t3.dwg` | 背景与索引；不据总说明推算具体座位坐标 |
| 宣传尺寸 | `VI/Liverse_Shanghai_Venue Introduction CHN 2026 v3(1).pdf` 第7页 | 作为待核对概况；与模型或图纸矛盾时不强行拼接 |

SKP 原生长度为英寸：`m = inch × 0.0254`。CAD多数文件设置为毫米；建筑图 X 的 `INSUNITS=0`，但文字实体 `18779` 明示“标高以米、其他尺寸以毫米”，因此按实体语义转换。不能拿当前全局 `DIMLFAC=0.001` 再统一缩放所有实体。

所有尺寸均指资料中的模型/设计尺寸，未经现场复测。表中小数保留到毫米只是阅读精度，不代表现场误差为1毫米。JSON保留更多位以便比较。

模型总览初选29个根组件：Group 0、1、2、11～22、52～63，Instance 8、9。它们的联合包围盒、原生变换和可见性见 JSON `geometry`；选择依据是主体组装位置和组件检查，进入正式建模时还需逐件核对含义。

Group 3～10 等参考图、远处 Instance 0/1 的重复“2层”、原点附近的屏幕拆件等不自动进入总览。不能对整个SKP直接执行“全部缩放到视野”。

建议暂定网页原点为原生 **(10.973863, 361.042760, 0.600000)**：使用观众地面前缘X、看台横向对称线Y和一楼地面Z。

```text
webX = nativeY - 361.042760
webY = nativeZ - 0.600000
webZ = nativeX - 10.973863
观众看舞台方向：-webZ
```

这是保持右手系的轴置换；原点仍是**暂定标定点**。正式舞台前沿中心、座号左右对应关系尚未确认，不据此输出座位真实坐标。

屋面高度不是全厅统一净高。看台、梁、灯桥和悬挂设备各自占用空间，不能用22.8减0.6就给所有座位配置相同净空。宣传册的建筑面积5500m²也不能用作座席区面积。

宣传册第7页的舞台口径：

| 项目 | 宣传值 | 本次判定 |
| --- | ---: | --- |
| 舞台前宽 | 20m | 概况参考 |
| 舞台中宽 | 17m | 对应纵深位置未明确 |
| 舞台后宽 | 13m | 概况参考 |
| 舞台深度 | 9m | 前后沿端点需对图 |
| 舞台面积 | 163m² | 与简单梯形推算不一致 |

计算：`(20+13)÷2×9 = 148.5m²`，比163m²少14.5m²。因此**不能把舞台简单画成20/13/9米的梯形，同时声称面积163m²**。SKP的425.229m²则包含后台，是另一种边界。正式表演台需从原模型/CAD划出闭合轮廓，保留凹口与折点。

JSON将这些拆分为26类未定参数，全部显式标为`unresolved`，没有默认的“标准椅宽”“标准眼高”或伪造的真实坐标。原模型未发现可直接对应1208编号的座椅实例映射；名称带`seats`的平面参考不视作已标定三维座椅。

## 8. 接下来怎样使用这份数据

1. **模型总览**：以原SKP主体几何为基础，分开壳体、楼板、看台、舞台、屏幕与设备。按联合包围盒取景，删除远处参考图及重复拆解模型，核对尺寸方向。
2. **座位落位**：导入1208条唯一座位身份；先标定舞台前沿、1F首末排、各区首末座、2F主要排面，再生成中心点与朝向。未确认的定位使用明确的预估状态，不标为真实。
3. **落位验收**：数量800/408、逐排编号连续、分块与表格一致；验证座椅脚下平面、椅间不重叠、通道与控台不被占用。二楼第二排保留9/8数量差，第一排三分块。
4. **观众视角后续处理**：排座和挡视结构完成标定后再放机位。当前尺寸包不能支持“已验证无遮挡”“精确视线比例”等结论。

优先需要解决的是四组参数：**一楼排座的米制定位；二楼排号到看台面的绑定及标高差；正式舞台边界；最终屏体版本与曲线**。其他几何可先复用SKP推进总览。

## 9. 提取与验证记录

- 座位表通过openpyxl只读提取，保留35排、1208个来源单元格与区块，不读取单元格尺寸作为物理比例。
- SKP通过已安装SketchUp原生C API递归读取，组合父子变换后转为米；整体文件包括多个离散图纸，所以主体经过显式筛选。
- CAD通过AutoCAD Core Console读取实体，选定记录附有handle。后续批处理均读取`tmp`副本，并检查来源文件哈希；不对原图执行保存。最初目录图的控制台自动保存已用原始备份恢复，哈希一致。
- 摘录原始面点不构成可靠的网格拓扑；精细几何必须从原SKP导出，不能依赖本JSON的AABB/无序顶点重建。
- 可重复计算：`node scripts/build-shanghai-dimensions.mjs`；检查生成物同步：`node scripts/build-shanghai-dimensions.mjs --check`。
- 自动校验：`node --test tests/shanghai-dimensions.test.mjs`，覆盖逐排数量/分块、1208座唯一性、来源一致性、空坐标约束、尺寸换算、台阶序列、屏幕像素推算与冲突保留。完整项目测试另行运行。

来源文件哈希和摘录用于锁定本次分析版本。该数据包是建模依据清单，**不是声称全部尺寸已齐备的竣工模型规格书**。
